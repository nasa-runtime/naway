# Governance

## Project Stewardship

Naway is maintained by repository maintainers appointed by the `nasa-runtime`
organization. Maintainers are responsible for roadmap stewardship, reviews,
releases, security response, and repository administration.

## Decision Making

Routine changes are accepted through pull-request review. Maintainers seek rough
consensus for changes affecting public protocols, compatibility, architecture,
security boundaries, or resource guarantees. When consensus cannot be reached,
the maintainers make the final decision based on project scope and long-term
maintainability, and document material tradeoffs in the pull request or issue.

## Contributions and Reviews

At least one maintainer approval is required before merging. Authors should not
approve their own changes. A maintainer may require additional review for security,
protocol, release, or breaking changes. Small documentation and maintenance changes
may use a proportionate review process.

## Releases

Maintainers select release scope, versioning, and timing. Release decisions account
for compatibility, migration cost, test evidence, performance gates, and known
security issues. Material user-visible changes must be recorded in `CHANGELOG.md`.

## Maintainer Changes

New maintainers may be invited based on sustained, constructive contributions and
demonstrated judgment. Maintainers may step down voluntarily. Access may be removed
for inactivity, security reasons, or repeated violations of project policy after
reasonable notice when circumstances permit.

## Conflicts of Interest

Maintainers must disclose material conflicts and recuse themselves when impartial
review is not possible. Security reports and Code of Conduct matters are handled
privately by uninvolved maintainers whenever practical.
