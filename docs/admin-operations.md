# 持久管理提案

候选可通过[结构化候选编辑接口](admin-draft-editing.md)按显式对象生成。编辑只返回原文，随后仍需
保存共享提案、审阅并由原目标执行；不把接入 Admin 的草稿结果当成集群发布。

多个 Admin 可以共用 PostgreSQL 中的同一集群提案。候选原文、摘要、目标意图、创建者、期限和
一次审阅结果持久保存，任一授权入口都能读取，Admin 重启不丢失这些事实。数据面不查询此数据库。

保存和审阅只产生提案事实，不自动发布配置。提案响应中的
`targets_validated: false`、`validation: "syntax_only"` 描述保存时的校验范围。
同时编译 `admin-operations-workflow-pgsql` 与 `node-actions` 时，`execution_supported` 为 `true`；
这仅表示制品提供执行入口，实际运行还要求独立执行开关、工作流存储和当前命令权威。
`approved` 表示审阅结果已提交；目标列表仍是提交者声明的意图，不能据此判断节点在线、权限一致、
基线正确或配置生效。原有配置管理接口保持各自的执行范围和合同。

## 配置和初始化

编译时启用 `admin-operations-pgsql`，在完整管理模式 `admin` 或 `all-in-one` 使用以下配置片段：

```yaml
admin:
  auth:
    enabled: true
    allowed_origins: ["https://admin.example.com"]
  rbac:
    enabled: true
    principals:
      - id: maker
        bearer_token: env://NAWAY_MAKER_TOKEN
        roles: [admin]
      - id: checker
        bearer_token: env://NAWAY_CHECKER_TOKEN
        roles: [admin]
  operations:
    enabled: true
    accept_proposals: true
    cluster_id: production
    database_url: env://NAWAY_ADMIN_DATABASE_URL
    schema: naway_operations
    max_records: 4096
    max_records_per_scope: 256
    max_candidate_bytes: 1048576
    max_total_candidate_bytes: 67108864
    workflow:
      enabled: false
    execution:
      enabled: false
    retention:
      enabled: false
      epoch_window_seconds: 900
      retain_seconds: 86400
      interval_seconds: 60
      batch_size: 32
```

数据库 URL 使用 PostgreSQL 连接格式，可通过既有 SecretSource 提供；不要把原始凭据放入请求。
浏览器保存和审阅要求 `admin.auth.allowed_origins` 显式允许页面的实际来源（协议、主机和端口）；
示例地址须替换为部署入口。仅持有有效凭据不绕过浏览器来源校验。
受管 schema 必须事先存在，专供这些操作表和迁移账本使用。连接必须直连 PostgreSQL 或使用
session pooling，以保持迁移锁所在的物理会话。数据库用户需要相应 schema 和表权限。

显式初始化使用：

```sh
naway --config /data/naway/naway.yml --admin-operations-migrate admin
```

命令应用嵌入的语义化迁移、核对结构后退出，不开放管理或业务监听。普通启动只验证迁移及结构，
不隐式建表。列、约束、索引、受检表属性、准入函数或触发器与迁移时保存的结构证据不符时拒绝启动。
追加迁移也先核对已有结构，不能将漂移覆盖登记为新基线。
结构证据保存在同一可信数据库中，不用于抵御数据库管理员篡改。

`enabled` 默认关闭。关闭时不解析数据库 SecretSource、不建池、不扫描操作记录。
纯 `data` 和 `sidecar` 不装配存储或开放这些接口。注册中心、配置中心和管理 gRPC 都不是提案存储
的前提。已启用的数据库身份和资源参数不能热更；`accept_proposals` 可以由本地受信配置热关闭或恢复。
关闭受理后仍允许授权读取和独立执行已批准提案。配置中心不能改变该管理权威或恢复被本地关闭的受理入口。

同一数据库中的 `cluster_id` 绑定共享容量合同，各 Admin 的启动配置必须一致。容量调整使用下述显式
维护命令；修改配置、普通启动和热更不能覆盖既有合同。达到上限后拒绝新提案，已有幂等记录仍可重放。
记录清理由下述独立保留策略控制，不提供任意删除接口。

## 提交、读取和审阅

入口为 `/api/operations/proposals`。查询参数 `domain` 支持 `gateway`（默认）、`sentinel`、
`interface-guard`；`workspace` 选择一个已授权工作区，省略时选择平台。每次请求只访问一个范围和领域。
工作区参数不能扩大管理主体的权限，也不从候选 YAML 推断对象归属。

`POST` 提交需要唯一的 `Idempotency-Key` 请求头及 JSON 正文：

```json
{
  "admission_epoch": 1,
  "domain": "gateway",
  "candidate": "schema_version: 1\nroutes: []\n",
  "ttl_seconds": 600,
  "targets": [{
    "node_id": "gateway-a",
    "boot_id": "observed-boot-id",
    "base_version": 12,
    "base_fingerprint": "0123456789abcdef"
  }]
}
```

领域必须与查询参数一致。候选只做有界 YAML 单文档语法校验，保留原始字节，不执行占位符或外部引用；
该校验不替代领域语义、工作区对象归属、逐节点基线及完整配置预检。最多 128 个唯一目标，编码后的
目标元数据合计最多 64 KiB；字段较长时可容纳的目标数量会相应减少。期限为
60～86400 秒，起点由数据库时钟确定。目标排序不改变意图，候选空白变化会改变摘要。

提交前通过 `GET /api/operations/proposals/context` 取得 `admission_epoch`、`epoch_expires_at_ms` 和
`epoch_required`，以及当前 `permissions` 和 `accept_proposals`；它使用同样的 `domain`、`workspace`
授权和并发预算。示例中的代际必须替换为实际值。低敏 JSON 响应包含实际 `cluster_id`，客户端应与
会话选择的集群核对，不应把另一集群的同名记录当作当前请求结果。
数据库在窗口到期后单调推进代际，多个 Admin 共用同一权威；主机时钟不参与裁决。
代际仅用于限定请求受理窗口，不代表目标租约、命令权限或节点 fencing。

幂等身份按集群、主体、范围和受理代际隔离。相同代际、键、内容、目标、期限和授权摘要返回原提案，不续期；
不同意图返回 `409`。保存候选与完成幂等收据共用 NASA 命名事务，不存在只保存其中一项的成功状态。
成功响应为 `200`，包含低敏 `proposal`，不回显候选正文、数据库地址或幂等键。
保留期内，同一范围与主体也不能在另一代际复用已有记录的键。单项及列表返回原 `admission_epoch`。
已保存的同意图可在窗口过后重放；没有收据的过期或未来代际请求返回 `410 admission_epoch_expired`。

尚未开启过保留策略的集群允许省略代际，按兼容协议保存。开启保留后，数据库永久要求新建请求显式携带
有效代际；旧进程漏传该字段也会被数据库插入门拒绝。已存在的兼容提案仍可按原身份重放。

`GET /api/operations/proposals/{id}` 读取单项；列表 `GET /api/operations/proposals` 支持
`limit=1..100` 和 `after` 游标，响应的 `next_after` 为空表示本次读取没有后续项。
游标按随机身份排序，不表示时间顺序，也不冻结整个分页期间的新提交。列表和单项均设置 `Cache-Control: no-store`。

`GET /api/operations/proposals/{id}/candidate` 返回保存的原始 YAML 字节，类型为
`application/yaml; charset=utf-8`，`ETag` 为 `"sha256-摘要"`，并设置 `no-store` 和 `nosniff`。
读取要求当前范围的读权限，并且是仍有写权限的创建者或当前审阅者；普通查看者和另一位工作区操作员
不能读取原文。原文可能包含提交者输入的秘密；读取不解析 SecretSource、不展开占位符，也不重新编码 YAML。
正文长度及 SHA-256 与持久事实不符时拒绝返回。

结果未知时，可向 `GET /api/operations/proposals/resolve` 提交原 `Idempotency-Key` 和
`Naway-Admission-Epoch` 请求头，结合原 `domain`、`workspace` 查找当前主体的共享记录。
此接口不创建提案，不要求重新发送候选，在受理关闭后仍可读取。`404` 只表示没有当前可见的保留记录，
不能证明另一请求尚在提交的事务已经回滚；不能因此自动换键或换代。

`POST /api/operations/proposals/{id}/review` 接收：

```json
{"decision":"approve","candidate_sha256":"已明确确认的候选 SHA-256"}
```

`decision` 支持 `approve`、`reject` 和 `cancel`。创建者只能取消自己的待审提案；批准和拒绝要求另一主体。
平台使用对应领域的读写权限。工作区读取、提交和审阅分别要求 `Read`、`Write`、`Review`，
因此操作员可提交，工作区管理员才可审阅。创建者当前写权限、认证目录及工作区绑定也会重新核对。
权限摘要变化、期限过去、候选摘要不一致或记录已经审阅时拒绝迁移。

持久状态为 `awaiting_approval`、`approved`、`rejected`、`cancelled`；待审或已批准提案过期时，
尚未创建执行时，读取按数据库时钟投影为 `expired`。`execution_started: true` 的提案保留已批准事实，
原执行不因提案期限而撤回。没有自动执行或自动续期；自动删除须显式启用保留策略。
认证摘要只约束提案审阅，不构成远程命令发行、跨节点 fencing 或撤销 epoch 的证明。

## 集群审阅页面

管理导航中的“变更提案”（`/operations`）展示当前入口、共享集群身份、授权工作区和领域。
三个领域共用列表、结构化目标录入、YAML 提交和双人审阅；页面列表每页 32 条、手动刷新和分页，只有显式查看才加载原文。
页面区分提案的语法校验与执行的逐目标收据，并在当前入口具备执行权威时提供显式执行按钮。
它不代替完整领域表单或语义比较；批准本身不证明目标预检或应用成功。

平台范围且拥有 `Cluster/Read` 时，可显式读取一次集群目标目录，逐个选取已就绪、同集群且具有完整
节点存储与原文基线的业务节点。纯 Admin、缺少基线、目录截断、身份冲突和过期状态会显示不可选原因。
目录最多保留六秒当前证据，包含服务端年龄和传输耗时；不会默认全选、后台轮询或把接入 Admin 视为整个集群。
工作区范围不读取平台目录，继续支持手工声明目标。

选取后，节点、boot、配置版本与指纹、存储身份、节点代际和原文 SHA-256 固定为只读目标行；
刷新目录或节点重启不会改写该声明。需要新的基线时，须明确移除旧行后重新选取。手工目标不附加
`node_baseline`，详情分别显示冻结基线或缺失标记。冻结只记录本次意图，不能替代执行前的实时复验和授权。

集群节点页另行展示当前本地文件决定。准备、正向恢复或反向恢复尚未结束时，不提供可选发布基线；
业务就绪仍单独显示，不能把“当前可转发”理解为“可以开始新发布”。节点报告过期时清除旧决定的
操作标识与提交序号。提案中已经冻结的声明保持原样，不随该实时观察改写。

每次保存前取得当前受理代际，冻结原正文、目标、期限和幂等键。失败或取消后不会自动换键重提；
页面允许显式原键重试或按原请求查找。可复制低敏恢复身份，到另一 Admin 以同一主体核查。
页面内仍持有原意图时，还会核对返回记录的候选摘要、目标和期限。原窗口过期不代表原提交未发生。

批准、拒绝和取消前须显式读取原文并确认摘要，创建者不能自行批准。审阅结果未知时先读取原记录，
不会自动重复审阅。切换范围、离开页面、退出和页面隐藏会取消读取并清除可见原文；迟到结果不回填。
隐藏页面时未知提交的冻结意图仅保留在当前页面内存，供恢复核查；退出或离开页面会丢弃该内存，
应先复制恢复身份。候选、凭据和幂等身份不写入浏览器存储或 URL。

## 绑定执行存储的集群身份

一个执行存储 schema 只允许属于一个 `cluster_id`，以便持久工作流和命令具有明确的集群范围。
未绑定时可存放多个集群的提案；绑定前必须没有其它集群记录。使用已初始化的专用 schema 查看状态：

```sh
naway --config /data/naway/naway.yml --admin-operations-execution-status admin
```

输出包括配置集群、`namespace.bound_cluster_id`、`namespace.bound_at_ms` 和
`namespace.matches_config`。未绑定时两个绑定字段均为 `null`，查看不会登记业务集群。
确认数据库、schema 和配置中的集群身份后，可显式绑定：

```sh
naway --config /data/naway/naway.yml --admin-operations-execution-bind admin
```

绑定永久保留，不能解绑、改换集群或通过清空提案重新开放。同集群重复调用返回原绑定和原时间；
不同集群并发只能有一个成功。已经存在其它集群时拒绝，不自动迁移或删除记录。新集群须使用另一
schema。数据库触发器同时约束旧进程的集群注册和身份更新；陈旧事务快照不能绕过集群边界。

命令仅允许完整管理模式，不启动监听或后台任务。成功提交后回包丢失时，结果为未知；保留原
cluster/schema，通过状态命令查看或原样重试，不能据此换身份再绑定。结构漂移、保护行缺失和
身份不符会阻止管理启动；现有数据转发不参与数据库绑定。

存储绑定不授予命令发行或节点动作权限，也不初始化 Saga 或开启执行。状态明确返回
`execution_available: false`，因为该维护命令不装配运行态权威；不能把绑定、批准或数据库提交视为配置已生效。

## 初始化工作流存储

`admin-operations-workflow-pgsql` 在提案能力之上启用 NASA PostgreSQL 工作流引擎。提案、Saga、
结果 Inbox 和命令 Outbox 共用同一命名 datasource 与四连接池，不向纯 Data 或 sidecar 引入数据库依赖。

先初始化提案结构，并使用前述命令永久绑定集群，再显式初始化工作流结构：

```sh
naway --config /data/naway/naway.yml --admin-operations-workflow-migrate admin
naway --config /data/naway/naway.yml --admin-operations-workflow-status admin
```

工作流初始化只接受没有既存 Saga/Inbox/Outbox 对象的命名空间，在一个数据库事务中创建完整结构、
初始化配额账本并保存结构证据。中途失败整体回滚。未确认完成时，保留原数据库、schema 和集群身份，
先查看状态再原样重试；不能把通信失败当成已经回滚。重复初始化核对已有合同，不覆盖未知结构。
普通 `--admin-operations-migrate` 不主动开启工作流初始化；已有工作流结构时仍验证其完整合同。

显式工作流迁移还安装独立的交付结构，保存冻结执行、目标占位和永久递增 fence；
`delivery_schema_installed` 单独表示这组结构已经通过实际校验。两个迁移各自原子提交，后段失败时
前段可能已存在，须保留原身份重试。普通启动及关闭运行开关后仍验证已安装的交付结构。
交付表不重复保存候选正文，未全部释放的执行最多 16 个，每份最多 128 个目标；
目标租约过期只能接管原操作，不能释放仍可能生效的另一操作或重置 fence。

`admin.operations.workflow.enabled: true` 让完整管理进程在启动时装配和校验工作流引擎，改变该开关
需要重启。普通启动只读复验，不执行 DDL；未绑定、未迁移、配额未初始化、异集群事实或在途定义
不一致都会拒绝就绪。关闭运行开关不回退已安装的结构门。

每种目标数量对应一个不可变定义，支持 1–128 个冻结目标。所有预检步骤排在所有应用步骤之前；
命令与结果使用引用，候选正文不复制到每个步骤。步骤期限为 30 秒，未知结果按 Poll 最多解决 300 秒，
迟到成功进入条件补偿。逻辑步骤归属不代替物理节点、启动身份或当前命令权限校验。

状态命令输出定义数量、目标上限和整体摘要。`context` 用 `workflow_schema_installed` 区分结构是否
存在，用 `workflow_storage_ready` 区分本入口是否已启用并完成启动验证。仅存储就绪不会推进 timer、
Outbox dispatcher 或节点动作；还须启用下面的执行能力并建立命令信任和目标持久收据。

## 执行已批准的集群变更

管理制品同时启用 `admin-operations-workflow-pgsql` 和 `node-actions`，完成前述初始化后，配置
`admin.operations.workflow.enabled: true`、`admin.operations.execution.enabled: true`，并启用
`admin.audit.enabled: true` 和 `admin.audit.fsync: true`。完整管理模式需具有受信命令发行者；
每个目标需初始化持久 journal 存储并开启 `admin.management.reporter.actions`，使用同集群 mTLS
管理连接和当前 RBAC。独立 Admin 不承担数据转发；all-in-one 可以同时管理集群和作为业务目标。

`context` 返回 `execution_supported`（制品能力）、`execution_enabled`（当前开关）、
`execution_ready` 和 `execution_reason`（当前可受理状态）。执行开关可以独立热更；关闭后暂停
本入口的命令、timer 和释放推进，不删除共享记录或目标恢复材料。其它有权 Admin 可继续原操作。
`accept_proposals` 只控制新提案和审阅，不控制已有执行。

显式提交 `POST /api/operations/proposals/{id}/execute?domain=sentinel`，工作区同时携带原
`workspace`。请求要求 `Content-Type: application/json`，正文最多 256 字节，仅允许一个字段：

```json
{"candidate_sha256":"原提案的完整小写 SHA-256"}
```

当前主体须拥有对应范围和领域的读写权限；原创建者与审阅者的当前身份和权限也须仍成立。
工作区的 Gateway 候选必须仅包含该工作区已委派的对象变更，完整原文不能夹带平台或其它工作区
字段。Sentinel 和 interface-guard 目前属于平台文件，工作区提案即使已审阅也不能取得其写权，
节点准备会拒绝这类候选。提案的保存范围不等于目标执行时的资源委派范围。
执行先持久记录审计意图，再在一个共享事务中固定原候选、全部目标与工作流。首次创建要求提案
未过期、目标当前 boot/存储/代际/原文基线一致；重放使用原身份，不重新采纳当前基线或创建第二次执行。
成功响应提供 `operation_id`、原摘要、目标数以及 `created`/`replayed`。

超时、断连或 `outcome_unknown` 不能证明事务没有提交。保留原提案 ID 和摘要，先读取原提案及
`GET /api/operations/proposals/{id}/execution`；不要换提案重复发布。共享推进锁忙时返回
`429 proposal_capacity`，这也不证明另一个入口没有创建原执行。

进度在同一数据库快照中读取完整原目标和 NASA 步骤，不随在线节点数缩小分母。准备、应用、准备补偿、
应用补偿的稳定收据分别展示；没有稳定证据表示未知。`Completed` 与 `Compensated` 是不同业务终态，
全部原节点持久关闭原受理代际且释放共享占位后，才显示 `lifecycle: complete`。
离线、失权、未知磁盘同步或缺少收据都不能冒充释放成功，旧请求不能关闭后来操作的代际。

节点收到正向 Resolve 时，单纯查不到收据仍不代表未执行。只有唯一真实工作许可、原节点目录和
受理代际、当前会话与权限均成立，且 Prepare 尚为空槽或 Apply 仍未形成受理及文件方向时，
才可在同一持久 head 中提交更高 fence 和“未受理且不再受理”的拒绝证明，然后回报
`node_effect_not_admitted`。迟到 Execute 只能得到该效果的原拒绝，不能重新应用；已有受理、
未知同步或文件方向保留原恢复责任。该证明不伪造业务 attempt 或收据，也不回答补偿方向的查询。
原 Saga 据此进入补偿并关闭原目标，不能把这类结果视作候选发布成功。

候选原文与当前文件相同也必须完成该动作的发布确认。节点已有正向或补偿文件决定时，
仍执行完整候选构建、资源准备、文件复验与快照发布，之后才持久记录成功；内容去重不能替代动作收据。

未受理证明与原因码需要管理端和目标端共同支持；旧制品不能解释新持久字段或原因码时拒绝继续，
不会将其视为成功。已经保存该证明的节点目录应使用支持它的制品恢复。

页面要求读取原文并确认 SHA-256 后才允许执行，不自动重投写请求。当前可见详情约每两秒读取一次
原执行，展示完整目标和独立释放进度；这不是监控历史。隐藏、退出、切换范围和撤销原文权限会清空
原文并取消旧读取。未知执行保留原身份供只读核查。

原目标主配置本身也是基线的一部分。all-in-one 同时作为原目标时，改写其主配置以暂停执行会改变
目标基线；恢复开关不授权采用新基线，原工作流可进入条件补偿。需要不改变目标文件的独立调度开关时，
应使用独立 Admin。节点命令仍逐次复验权限、会话、租约和持久 fence；共享数据库不可用时，已发布
数据路由继续服务，管理推进停止。

## 调整共享容量

四项预算分别为集群总记录数、每个范围的记录数、单候选字节和候选总字节。记录数为 1～4096，
每范围不超过总数，单候选为 1024～1048576 字节，总字节不低于单候选且不超过 67108864。
所有保留状态均占容量；已批准、已过期或执行引用保护的记录不会为缩容被自动驱逐。

维护使用完整管理制品和 `admin` 或 `all-in-one` 模式，不开放监听，不启动清理器。
先使用目标集群配置读取当前合同：

```sh
naway --config /data/naway/naway.yml --admin-operations-capacity-status admin
```

输出包括实际 `limits`、`revision` 和可原样复制的 `expected` 令牌，不包含数据库凭据或候选。
查看不创建集群，也不修改预算。数据库必须已通过显式结构迁移，集群须由正常启用的 Admin 登记。
在独立配置副本中准备目标四项预算，保持数据库、schema 和 `cluster_id` 身份不变，再执行：

```sh
naway --config /data/naway/capacity-target.yml --admin-operations-capacity-expected '<原 revision:sha256>' admin
```

将引号内的占位文本替换为刚读取的完整 `expected`。维护进程在集群行锁内比较原修订和摘要，
数据库检查现存总数、每范围数量、最大候选和总字节全部满足新预算后，才同事务更新四项实值、摘要、
前驱摘要与单调修订。超出任一目标预算时整次调整拒绝，不修改保留策略或受理代际。

并发不同调整只有一个能消费原令牌；容量从一组值改为另一组再改回来，旧令牌仍然失效。
相同请求重试只有在紧邻前驱、目标四项和新修订全部吻合时返回已经满足的合同，不重复推进。
COMMIT 回包丢失时命令报告结果未知，应保留原令牌和目标配置，使用状态命令核查或原样重试，
不能自动用新令牌覆盖其它人的调整。

明确成功后，为各 Admin 更新相同预算并重启。仍运行的入口会在 `context` 中报告
`capacity.matches_config: false` 并停止新建，页面提示更新配置；已有记录和原身份恢复继续可用。
原文读取仍受入口自己的单候选资源上限约束，扩容后新出现的大候选应从已更新入口读取。
数据库容量触发器也约束未升级 writer 的插入，即使其内存预算较大，也不能突破缩容后的共享预算。
数据转发不参与容量维护，数据库不可用只阻止依赖它的管理操作。

旧集群在追加结构后首次由同摘要配置启动时，补齐实际容量并登记修订；不会用不同配置覆盖原摘要。
容量触发器、函数或约束漂移会阻止后续管理启动和维护，不能用再次初始化覆盖异常结构。

## 有限保留

`retention.enabled` 默认关闭。开启后，每个 Admin 只有一个周期任务，复用现有连接池；各入口通过
同一集群行锁协调有限批次，不需要另选主。受理窗口为 60～86400 秒，保留期为受理窗口至 2678400 秒，
清理间隔为 1～3600 秒，每批 1～128 条。所有字段属于启动资源，不能热更。

第一次开启时，数据库同事务登记保留合同、关闭兼容协议新建能力并推进受理代际。之前取得的窗口不再
允许新建，已有收据继续可读。后续启用节点必须使用完全相同的合同；不同窗口、保留期、周期或批量拒绝启动。
关闭清理不删除合同，也不恢复无代际新建。现有合同不能通过修改配置或重启覆盖。

仅清理从未进入执行且属于旧代际的提案。拒绝和取消从最后状态变更时刻计算保留期；待审和已批准提案
从自身到期时刻计算。当前受理代际、执行标记或执行引用保护的事实不删除。
每条提案与它精确匹配的已完成幂等收据同事务删除；缺失或不一致的收据、外键引用及未知提交都不会被
当作已释放容量。数据库不可用时停止本轮，下一轮重新依据持久事实裁决，不积压后台队列。

客户端必须保存原代际和原幂等键。记录清理后，按原身份重放提交返回 `410`，只读查找返回 `404`，
不能重新创建；不要自动换新代际或新键
重试结果未知的业务动作。本功能提供有限重试窗口，不提供永久随机键去重或长期归档。
逻辑记录删除不表示 PostgreSQL 物理文件立即缩小；MVCC 与物理空间回收由数据库维护。

## 容量和失败语义

每个 Admin 最多 8 个并发提案请求；每个工作区沿用独立的 2 个管理名额。正文收取最多 5 秒，
连接池最多 4 条连接，获取最多 2 秒，单条 SQL 最多 3 秒，空闲事务最多 5 秒，整个事务最多 10 秒。
只读查询还有覆盖取连接、网络回包和连接归还的 6 秒绝对期限。未完成读取时丢弃物理连接，成功读取后
归还连接的协议清理最多 2 秒；取消或超时不遗留无期限后台探测占用池容量。
请求缓冲按单候选上限保守覆盖 JSON 转义和目标元数据。原文只保存一次，不在数据转发路径编码、复制或读取。

跨 Admin 总记录数、每域记录数和候选总字节由同一数据库事务锁保护。所有状态都计入保留容量，
未确认记录不会被驱逐来给新请求腾位置；过期记录也必须满足显式保留合同才清理。
`429 proposal_capacity` 表示并发或持久容量不足，不会建立后台无界等待队列。

数据库不可用返回 `503 authority_unavailable`。COMMIT 回包丢失、事务整体超时或回滚结果不确定时，
返回 `503 outcome_unknown`，不声称已经回滚。提交方应保持原代际、原幂等键和完全相同的意图重试；
审阅方应读取原提案、摘要和审阅结果后决定下一步，不能自动生成新动作。候选和原始数据库错误不进入错误响应。

数据库故障不会撤下已成功发布的数据路由；依赖该数据库的管理动作停止受理。
这些持久控制事实与内置实时监控分开，实时监控仍然不保存历史。
