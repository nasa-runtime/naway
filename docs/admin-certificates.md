# 集群活动证书

管理端口的 `/certificates` 展示各节点业务监听器实际安装的公开叶证书。HTTPS、HTTP/3 和
终止 TLS 的 TCP stream 分别记录，默认身份和每个 SNI 绑定分别展示。多个 Admin 通过管理
gRPC 汇聚同一集群的当前事实；纯 Admin 节点显示不承载业务 TLS。

## 安装事实与证书状态

目录包含入口、协议、选证名称、通配选择顺序、来源类型、叶证书 DER 的 SHA-256、有效期、
有限的 DNS/URI/IP SAN、OCSP 截止时间及强制要求，以及工作区、租户和环境。默认身份的绑定
名称为空；精确 SNI 优先于通配项，通配顺序来自实际选择器。不同节点的材料或状态分别显示。
目录不包含 PEM、DER 正文、私钥、秘密文件路径、会话密钥或任意来源诊断文本。

事实来自构建 TLS 配置时实际使用的证书，并在监听器安装成功后发布。文件被替换但证书与私钥
不匹配时，业务监听器继续使用此前有效材料，目录也保留该安装事实。监听器被替换或停止后，旧
持有者失去发布权，迟到的文件观察结果不能覆盖新材料。HTTP/3 只有端点实际接受新配置后才
更新事实；会话缓存轮换共享当前选证器，不重新读取文件。

来源包括 `file`、`manifest`、`acme`、`sds` 和 `spire`。SPIRE 从当前获权来源观察材料，身份
变化、撤权或到期会更新目录，不把首次构建时的证书当作永久状态。安装状态含义如下：

| 状态 | 含义 |
| --- | --- |
| `complete` | 已取得当前安装材料的完整公开身份 |
| `pending` | 当前配置对应的监听器尚无匹配安装事实 |
| `waiting` | 监听器等待可用身份，例如 ACME 首次材料 |
| `unauthorized` | 动态身份当前未获授权或已不可继续使用 |
| `unavailable` | 无法提供完整的公开身份观察值 |

已安装不保证握手成功：客户端仍须验证信任链、名称、有效期与其它认证条件。页面到期提示按
当前查看设备的时钟估算，OCSP 截止和强制拒绝门独立显示。此目录不枚举管理 gRPC、边缘控制
连接或上游客户端 TLS 身份，也不保存历史证书。

## 集群覆盖与权限

平台接口为 `GET /api/cluster/certificates`，同时要求 `cluster/read` 和 `certs/read`。
工作区接口为 `GET /api/workspaces/{workspace}/cluster/certificates`，使用当前工作区读取权
和平台明确声明的 `cluster_nodes`。未声明成员返回 `unconfigured`，不回退到本机目录。

工作区读取需要每个节点同配置代的对象目录权限证明。证书归属取所属入口或 stream 的实际
证书对象归属，必须同时匹配工作区、租户和环境；授权过滤先于搜索与分页。权限分歧返回
`authority_mismatch`，未收到完整目录或证明为 `pending`，缺能力为 `unsupported`，失联为
`stale`，尚无事实为 `unknown`，身份冲突为 `identity_conflict`，超出观察预算为 `capacity`。

每条绑定区分已安装数量 `present`、明确缺失 `missing`、不承载业务 TLS 的 `not_serving`
和事实不足的 `unknown`。只有完整且获权的目录才能证明缺失；整个监听器仍在等待身份时，
不能把尚未观察到的 SNI 判为已删除。纯 Admin 的完整空目录计入覆盖，但不计为证书已安装。
所有声明成员都保留在分母中，成员发现不完整也不能解释为全集群完整。

## 查询与显示有效期

接口接受 `search`、`offset`、`limit`。搜索区分大小写，匹配入口、协议、绑定名称和 SAN，
最多64字节；每页1至100项，缺省25项，偏移不超过4096。重复、未知或非法参数返回400。
跨节点最多汇聚4096个匹配绑定；超量返回503，需要缩小搜索范围。

`ETag` 包含授权范围、节点配置和证书材料向量；即使配置版本不变，证书热换也会改变它。
后续页必须携带 `If-Match`，缺少返回428，事实换代返回412，应重新读取第一页。不同 Admin
在当前事实相同时生成相同分页身份。响应最多4 MiB，与对象目录共用八个读取许可，繁忙返回
429；平台采样不可用返回202，交付前本机授权配置变化返回409。

页面每两秒读取当前页，把样本年龄和网络耗时纳入六秒显示期限。搜索、范围和页码切换会退休
旧请求；暂停、隐藏、退出、失败和超龄都会清除旧事实。401、403或404停止自动读取，恢复须
显式操作并重新获得服务端授权。页面不提供历史查询。

## 传输与资源边界

节点在材料构建或授权变化时生成低敏事实，使用 `Arc` 共享；不为管理查询重读证书文件，也不
增加代理请求或 TLS 握手路径的锁、X.509 解析或序列化。每个 TLS 计划最多观察512个绑定、
512 KiB，单叶最多32个 SAN，每个 DNS/URI 文本最多512字节；注册表最多观察1024个监听器。
超过观察容量不停止合法的 TLS 服务，但目录必须报告容量不足，不能交付半份清单。

管理 `Report` 声明当前证书目录摘要，独立 `Certificates` RPC 复用既有 mTLS、证书与节点
绑定、boot/session 和配置权限。摘要变化即撤下旧完整目录，即使配置版本不变；分片仅接受
最近一次获权心跳声明的摘要，不允许迟到材料倒退。缺能力时保持 `unsupported`。

每节点目录最多2048项、512 KiB，证书接收槽共享64 MiB。每片最多16项且编码负载不超过
24 KiB，每轮最多八片；与其它目录串行复用一个发送槽，另一个用于指标，不增加两条在途 RPC
上限。偏移连续、排序唯一、重放一致、字段组合及完整摘要通过后才发布；分片不会续期心跳。
会话退休、配置换代、能力撤销或材料摘要变化使旧目录失效。

## 材料管理边界

此页面提供集群读取。本机 `/api/certs` 的文件材料信息不代表集群实际安装状态；叶证书 DER
摘要也不是 PEM 文件条件写入所用的 ETag。此目录不接收材料上传，不提供跨节点原子换证或
持久交付收据。证书文件写入、审批、条件替换及失败补偿需要独立的材料交付流程，不能把目录
已更新当作所有目标已经接受某次写入。

本机 `POST /api/certs` 接受 HTTP proxy 与 TCP stream 的默认或 SNI 文件身份。请求使用
`application/json`，正文包含 `target`、`certificate_pem` 和 `private_key_pem`，总请求及材料
受2 MiB上限保护。`target` 包含 `kind`（`proxy` 或 `stream`）、`listener`（配置入口标识）和
`entry`（`default` 或 `sni-0` 等零起始声明序号）。目标可直接取自本机 `/api/certs` 对应条目，
不接受文件路径。SNI 序号只在原配置代内有效，重排后须重新读取。兼容正文中的单独 `proxy`
字段表示该 proxy 默认身份；`proxy` 和 `target` 只能选择一个。
`If-Match` 取自 `/api/config/current`，`X-Naway-Certificate-If-Match` 取自本机 `/api/certs`
对应条目的 PEM ETag；两者均须仍匹配。SDS、SPIRE 与外部 signer 身份拒绝文件上传。

材料请求在正文接收和排队之后重新认证，并核对原提交者当前仍拥有 `certs/write`。实际安装与
配置发布共用协调器，在配置文件读事务和证书安装锁内保持固定锁顺序；受管配置写者、ACME
续期和其它本机上传不能穿插条件比较与材料写入。最多两个安装任务，等待配置发布权超过两秒
返回429。HTTP 取消后，已经进入阻塞线程的任务仍持有全部许可直到实际结束。

成功响应的 `installed` 表示文件材料已经提交；应通过集群活动目录和实际连接核对每种协议的
当前身份。文件提交或完成审计期间可能产生不确定结果，断线不能解释为没有执行，不能无条件
重传。启用本机 maker-checker 时先返回202，审阅仍经过同一最终安装门；其队列不提供跨 Admin
持久收据。手动改文件的外部进程不受进程内协调器约束，不能据此声称任意外部写入具有条件事务保证。

本机与 ACME 文件安装在写入前复用实际身份加载的 must-staple 和 OCSP 校验。仅证书与私钥匹配
并不足以安装：新证书要求 staple 却没有响应策略，或当前响应不属于新证书、已过期、签名无效，
均拒绝候选并保留原文件。SNI 上传使用自己的 OCSP 策略，不继承默认身份的 ACME、manifest 或响应。

本机手工安装还在材料锁内预检所有共享该来源的监听器，包括其它 SNI、客户端 CA 与会话策略。
候选私钥只解析一次，完整配置构建不发布到活动监听器；任一相关策略不成立即拒绝本次材料决定。
只共享一个文件、外部 signer 共享证书或不同来源复用不可变目录时拒绝覆盖。首次创建 manifest
只激活新目录，不改原 seed，继续使用 seed 的独立监听器保持原材料。预检最多检查4096个声明身份，
超过上限拒绝安装。ACME 的来源级策略门不等同此完整手工预检，两者均不替代文件决定后的实际安装确认。

本机上传以400和 `invalid_certificate_material` 表示候选不满足当前身份策略；旧材料基线无法
读取时以503和 `certificate_storage_unavailable` 拒绝。恢复或文件决定阶段无法证明完成时，
以503和 `certificate_installation_outcome_unknown` 表示结果未知，应重新读取原目标的材料与
实际监听事实。错误响应不返回私钥、上传字段名、底层解析文本或内部文件路径。

受管安装为每次文件决定生成独立材料代，相同 PEM 的再次安装也会推进该代。本机文件身份的
`status.material_generation` 返回已记录且与公开证书一致的令牌；未受管材料为null，读取不创建
归属记录。普通材料代投影不读取私钥；存在未完成的双文件journal时，仍须先核对完整pair并恢复。
令牌是条件写入证据，不能替代配置权限或实际安装事实。上传可额外携带
`X-Naway-Material-If-Match`，要求完整证书与私钥仍属于该代；不匹配返回412和
`certificate_material_generation_changed`。旧请求即使再次遇到相同证书摘要，也不能沿用已退休
的代。未提供该头的兼容上传仍只使用原配置及PEM条件，不具有材料代保护。成功响应返回新代，
本机审批同时冻结材料目标、原PEM和可选材料代。

材料代在文件决定前预分配并绑定完整pair。双文件恢复journal同时保存原/新材料代，先提交
完整pair及代，再退休journal并清理备份；manifest在完整材料目录与归属元数据持久化后才切换指针。
双文件恢复只确认原事务的完整新pair，或在当前每个文件均属于原旧新边界且必要备份验证通过后，
恢复旧pair及原代。其它材料代即使具有相同字节也视为接管；未知文件内容、已提交新代之后的
不完整pair、缺失或损坏的必要备份均保留活动journal并拒绝覆盖。完整新pair与精确新代已经
提交时，可直接结算原事务，无须旧回滚备份。无材料代的旧格式事务不能接管已有受管代。

已退休journal的清理失败可能留下备份；应先确认它不再是活动恢复入口再处理。材料元数据
损坏或恢复证据不足不撤销已经安装的TLS身份，但后续材料加载及管理写入会被保护门拒绝。

不同manifest共享父目录时，自动回收只处理具有本manifest归属证据的旧目录；其它来源、
无归属记录或损坏的目录保留。生成的材料目录只供其所属manifest使用，不应手工跨来源复用。
目录别名按实际父目录统一，外部文件进程和旧二进制写者仍不属于进程内受管事务保证范围。

## 原目标本机材料条件

需要确认文件材料条件时，全功能实例提供按需的 `POST /api/certs/conditions`。此入口要求
`certs/read` 与 `cluster/read`，不向工作区身份开放平台来源关系；纯 Admin 与 Data 的 HTTP
入口返回404。集群活动页面继续采用上述跨节点安装目录，此维护接口返回 `scope: local`，
不能作为远端目标的替代查询，也不授予材料安装或集群交付权。

请求为最多2048字节的 `application/json`，字段为 `target`、`boot_id`、`base_version` 和
`base_fingerprint`。目标格式与本机上传一致；启动、版本与16位小写十六进制指纹取自该节点的
`GET /admin/cluster/facts`，必须全部匹配。未知字段、额外查询参数和非法目标返回400。

成功响应的 `conditions` 包含公开证书 PEM ETag、可空的 `material_generation`、来源类别
`source`（`file`、`manifest` 或 `acme`）、稳定的 `source_id` 和完整 `affected` 逻辑身份。
来源证明根据实际父目录与文件槽位计算，不包含路径或私钥摘要；同源的多个逻辑身份具有相同
证明。尚未激活的 manifest 读取 seed，但拥有独立写入来源：修改 seed 可能影响它，首次激活
manifest 不改 seed，因此不能只按证书字节相同就合并写入动作。

查询不创建材料代，不收养旧文件，不写候选，不发布监听配置；`execution_supported` 始终为
false。普通查询只读公开证书与归属，已有未完成的双文件事务仍按既定规则恢复。证书文件必须
仅包含一至32个可解析的 X.509 `CERTIFICATE` 块及空白；其它 PEM 块、前后附加文本、
私钥错放或材料损坏时不返回摘要。
读取结果不验证当前私钥仍属于该代，正式条件安装仍必须在材料锁内验证完整 pair。

每节点有两个独立的实际读取许可，配置发布权等待最多两秒。读取保持配置协调器、文件读事务、
材料锁的顺序；HTTP 取消后实际阻塞任务完成才释放许可。最多检查4096个声明身份，完整影响最多
128项；超量返回429，不能截断结果。原启动或配置变化返回412，目标缺失404，外部来源或完整
影响无法证明返回409，存储或材料证据不可用返回503。响应禁止缓存，交付前重新验证当前权限。
外部直接修改文件的进程不受这些进程内锁约束；条件快照不能代替安装时的再次复验。

## 集群原目标材料条件

任一具有管理发行能力的 Admin 可通过 `POST /api/certificate-conditions`，让原节点批量观察
文件材料条件。工作区使用 `?workspace={id}`。此能力使用 `node-actions`，目标无需 PostgreSQL
或材料提案存储。每个目标须初始化并挂接本地 journal，使用本地文件配置、认证和 RBAC，显式开启：

```yaml
admin:
  management:
    reporter:
      material_previews: true
```

`material_previews` 默认关闭，独立于配置预览 `previews`、执行 `actions`、材料提案受理和
注册中心、配置中心开关。目标沿现有 mTLS 主动上报连接接收独立签名命令；每个上报目标须配置
同集群可信发行者。all-in-one 查询自身时共享原生结果，不经过内部 JSON 或 protobuf。
纯 Data 不开放此 HTTP 聚合入口，但可以执行获权的节点观察。

平台请求者须同时拥有 `certificate-proposals/read`、`certs/read` 和 `cluster/read`；工作区
请求者须拥有当前工作区读取权，且所有原节点属于声明的 `cluster_nodes`。发行端和目标端都会
复验当前主体及对象归属。同源的其它监听身份也必须全部属于请求范围；任一共享身份越界，整批
节点结果为 `denied`，不泄露其它工作区的影响清单。

正文为 `application/json`，包含 `targets` 数组，最多128项、128 KiB。每项必须显式提供
`node_id`、`boot_id`、`base_version`、`base_fingerprint`、`node_baseline` 和 `target`。
原节点配置事实和完整持久基线取自集群概览的对应节点；缺失时不能由接入 Admin 补成当前值。
`target` 使用上述逻辑身份格式，同节点全部目标必须具有相同原基线，重复目标和未知字段拒绝。

响应包含 `query_id`、`scope`、`target_count`、`complete_count` 和 `nodes`。每个节点保留
原节点身份、基线、`targets` 与原请求的零起始 `indices`；成功状态为 `complete`，其
`conditions.entries` 与该节点目标顺序一致。每个条目以 `group` 引用 `conditions.groups`，
并独立标明 `source`。同一物理写入来源只返回一份公开条件和完整 `affected`，保留尚未激活
manifest 与 seed 的独立写入权威。节点批次任一目标失败时，整批状态为 `unavailable`，没有
部分条件；失败节点始终保留在原分母内。

`reason` 为有限分类：`unsupported`、`disabled`、`unavailable`、`capacity`、`expired`、
`denied`、`baseline_changed`、`target_absent`、`external_source`、`storage` 或
`impact_unproven`。失败不能解释为材料未变。结果交付前再次检查全部成功节点的原启动、会话、
配置及持久基线，并复验当前请求者；整个观察窗口最多20秒，超期不保留先前完成的成功。

每个 Admin 同时最多两个聚合请求，工作区也受两个请求配额限制；最多128个远端投递槽，每节点
每入口一个槽。每个目标有两个实际读取许可，单节点完整条件预算24 KiB，超量整批失败。
同节点来源索引与公开证书按批次复用，不逐目标重复解析同源材料；管理连接维持原有两个在途 RPC
预算。HTTP 输出借用原生条件直接编码，不产生 JSON 中间树。取消不会提前释放仍在工作的读取许可。

普通读取不打开私钥，不创建材料代或候选文件；已有双文件 journal 的必要恢复仍检查完整 pair。
结果带 `Cache-Control: no-store`，`execution_supported` 为 false。此接口不提供候选材料预检、
审批、安装或持久交付，也不代替正式写入时的条件与权限复验。

## 集群实际安装观察

`POST /api/certificate-installations` 使用独立默认关闭的 `reporter.material_installations`，
按相同原目标基线取得完整文件条件及实际加载事实。它区分完整观察与全部共享协议已经安装，
不会用磁盘材料代或相同叶证书代替监听器加载证明。部署、返回字段与失败语义见
[集群证书实际安装观察](admin-certificate-installations.md)。

## 原加密提案的目标预检

`POST /api/certificate-proposals/{id}/preview` 使用原持久材料提案，工作区传
`?workspace={id}`，请求正文只能是 `{}`。请求不能替换候选、节点、启动身份、配置或材料条件。
发行 Admin 需要 `admin-operations-pgsql` 和 `node-actions`，并配置共享材料存储与管理发行身份。
目标只需 `node-actions` 和原节点 journal，不需要数据库或 Admin 的材料解密钥环。

每个目标显式开启 `admin.management.reporter.material_previews`。此开关默认关闭，独立于
YAML 预览、持久动作、注册中心与配置中心。协议单独协商候选预检能力；只支持公开材料条件查询
的节点返回 `unsupported`。材料存储仍须启用；`certificates.accept_proposals=false` 只关闭新的
材料受理，原有有效提案仍可预检。纯 Admin 不能作为实际 TLS 目标。

当前请求者和原创建者都必须拥有当前范围的材料写入权限。平台要求 `certificate-proposals`、
`certs`、`cluster` 的写权限；工作区要求当前成员动作、原节点范围及所有原对象归属。节点还会
检查同一物理来源影响的全部共享监听。任一共享对象越界时整节点失败，响应不返回该节点的条件
或外部对象名称。仅有读取或审阅权限不能触发候选下载和完整 TLS 依赖读取。

只接受未过期的 `awaiting_approval` 或 `approved` 原记录。Admin 认证原存储、受理代、创建者、
意图、完整目标与公开摘要后解密一次，通过同一材料帧服务本次请求。节点下载前核对原 boot、配置、
持久基线、公开证书 ETag、受管材料代及完整 pair，私钥单独改变也会拒绝。候选完整接收后重新核对
这些条件，并把同节点选中的所有来源同时覆盖到候选，构建全部受影响监听的 TLS、SNI、OCSP、
客户端 CA 与会话策略。未受管材料不会因预检被接管；预检不写候选文件、不推进材料代、不发布
活动监听。已有未完成文件事务按既有恢复规则处理。

完整 pair 预检持有原父目录、证书、私钥、归属记录与 manifest 指针的文件句柄，直到同节点
全部来源和监听策略检查结束。返回前复验声明位置、原目录及文件身份，并核对原指针与归属
原文摘要。链接或非普通写入来源返回存储拒绝；日常 TLS 加载仍支持指向普通文件的 Secret
轮换链接。这里的来源观察不锁定其它进程，也不授予后续文件写入资格。

每个 Admin 最多同时受理两份预检，每个目标最多两个真实材料工作；远端每节点一个短期槽，最多
128 个槽。原目标不超过128个，同节点声明与结果各不超过24 KiB，分片不超过16 KiB，原生材料帧
不超过1 MiB加16字节。原记录认证完成后，节点预检使用不超过20秒的共同签名窗口，并受原提案
有效期约束。该窗口内的排队与最终复验计入原期限；单节点失联或拒绝始终保留原目标分母。
HTTP 输出最多4 MiB，超量整份拒绝。

原材料预检的证书和私钥各不超过1 MiB，直接从原两个句柄填入一次分配的清零帧，再借用
其中的切片，不分别聚合后重新拼接。原长度、完整读取或 EOF 不一致时拒绝并清零；候选网络
帧仍保持上述1 MiB总预算。原 pair 只用于本次完整归属检查，不保存为持久备份。

响应中的 `targets` 是完整原目标，`nodes[].target_indices` 引用其原位置。成功节点提供去重的
`conditions` 和本次完整来源影响的 `impact_sha256`，失败节点提供固定 `reason`。公开
`certificate` 描述候选证书，不含私钥或材料帧摘要。只有全部节点成功时 `targets_validated` 才为
true；`execution_supported` 始终为 false。返回前再次核对原记录状态、密文摘要、当前授权、原
节点基线和期限。取消或审阅改变原记录后，不交付此前取得的成功。

同进程路径共享原生材料，不经过 JSON 或 protobuf；网络只在实际边界编码有界二进制分片。
受控材料帧和接收缓冲区在最后持有者退出时清零。取消等待不会提前释放仍在构建任务中的材料及
实际名额；这一保证不扩张到 TLS、protobuf 或密码学依赖内部的全部存储。

预检证明是一份短期观察。原提案只绑定 pair 条件，未提前批准本次新观察到的来源影响摘要，旧批准
不会因此取得执行资格。此接口不提供跨节点原子换证、持久交付收据或失败补偿；正式材料决定必须
重新证明当前权限、原条件和完整影响。

需要跨 Admin 冻结并明确确认这份完整影响时，可独立启用[完整影响审批](admin-certificate-impact.md)。
服务端只登记全部原目标成功的证明，采用独立共享容量和双人审阅；材料提案与影响记录分别保留
自己的状态。批准不安装材料，当前仍不提供持久材料交付、监听收据或条件补偿。

## 独立材料提案

需要跨 Admin 保存和审阅材料时，可启用[加密证书提案](admin-certificate-proposals.md)。
其读取不暴露私钥，批准不会触发换证；当前活动目录、材料受理状态和本机文件安装保持不同语义。
