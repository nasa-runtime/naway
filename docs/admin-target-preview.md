# 原目标配置预览

集群提案可以由任一具备发行能力的 Admin 发起只读预览。每个原目标使用自己的完整配置构建器，
比较原活动配置与提案候选，返回路由、上游、监听、Sentinel、接口守卫的对象增删改身份。
接入 Admin 的本地配置不会替代 Data 节点的配置。全部原目标始终保留，离线或失败节点不会从分母删除。

预览只提供当前审阅事实，不批准提案、不修改活动文件、不发布数据面，也不创建持久执行记录。
正式审批与执行仍需各自的当前权限、原审批、原目标、租约及持久决定验证。候选构建可能读取
本地文件和远程秘密依赖，因此预览要求实际构建资格，普通只读权限不能触发构建。

## 部署与授权

发行 Admin 的制品需要 `admin-operations-workflow-pgsql` 和 `node-actions`，配置共享提案存储及
同集群管理发行者。`admin.operations.execution.enabled` 可以保持关闭，预览不依赖执行开关。
目标制品只需 `node-actions`，不需要 PostgreSQL 驱动或共享数据库连接。

每个目标必须初始化并挂接本地 journal 存储，使用本地文件配置、认证和 RBAC，再显式设置：

```yaml
admin:
  management:
    reporter:
      previews: true
```

`previews` 默认关闭，与 `reporter.actions` 独立。上报目标必须配置当前可信发行者和 mTLS；其余
连接配置沿用[集群管理配置](../README.md)。独立 Data 沿主动上报连接收取命令、分片读取原文并
回报结果，不要求新增入站 HTTP 管理端口。all-in-one 预览自身目标时直接共享 Bytes 和原生结果，
不经过 protobuf 或内部 JSON。动作与预览共用单连接后台 RPC 预算，心跳独立继续。

平台请求者需要对应领域的 `read`、`dry-run` 权限；工作区请求者需要该工作区的读取和写入权限。
原创建者也必须保留当前写入资格。原提案冻结的认证和工作区权威须仍一致，工作区仅能预览
允许的网关对象替换，全局 Sentinel 与接口守卫文档不借工作区入口开放。

## 接口与结果

`POST /api/operations/proposals/{id}/preview?domain=sentinel` 接收 `Content-Type: application/json`
及空对象 `{}`。领域还可为 `gateway`、`interface-guard`；工作区使用相同接口的 `workspace` 参数。
客户端不能提供新正文、目标或摘要，原始候选与完整目标集合只从已授权的共享提案读取。

仅支持有受理代际、尚未过期、未执行且处于 `awaiting_approval` 或 `approved` 的提案。受理窗口
轮换不撤销已保存提案自己的有效期限。开始与返回前都会复验原状态、摘要、全部目标和当前权限；
期间提案被取消、拒绝、批准或开始执行时，需要重新发起预览。

响应带 `Cache-Control: no-store`，`scope` 为 `original_targets`，包含原提案身份、字符串受理代际、
原范围、领域、候选 SHA-256、本次签发与到期时间、`target_count` 和全部 `targets`。
每行 `target` 是原冻结目标，成功时 `status` 为 `succeeded` 并携带完整五领域 `diff`；失败时
`status` 为 `failed`，仅携带有限原因：

| 原因 | 含义 |
| --- | --- |
| `unsupported` | 原目标制品或角色不支持预览 |
| `disabled` | 原目标未开启预览 |
| `unavailable` | 原目标、当前连接或持久基线不可用 |
| `capacity` | 构建名额不足或完整差异超过结果预算 |
| `expired` | 本次短期等待或签名期限已结束 |
| `denied` | 当前预览授权不成立 |
| `baseline_changed` | 原启动、会话、配置或持久基线已经变化 |
| `candidate_invalid` | 该原目标的完整候选构建未通过 |

失败行没有差异，不能解释为“没有变化”。结果不含配置原文、秘密、文件路径或内部错误链。
目标以原 node、boot、配置版本和指纹、store、节点受理代际、三文档身份共同绑定；重启或配置
换代后不得改绑新目标。独立签名用途、当前会话、绝对期限与单调时钟共同限制交付资格。

## 容量与生命周期

每个 Admin 最多同时处理两个完整预览请求，先取得名额再读取候选；最多128个原目标及128个
远程投递槽，每节点每入口一个槽。共享原文最多1MiB，以16KiB分片传输；节点最多两个预览工作，
同时受通用候选构建容量限制。每目标结果最多256个变更身份，身份原文合计16KiB，JSON转义后
合计24KiB。超限整份失败，不截断成功。管理结果在32KiB协议消息预算内，页面只为精确预览
接口提供4MiB响应预算。

确认正文等待最多5秒，随后整个预览等待最多20秒，源提案剩余期限还会进一步缩短可用窗口。
取消请求会回收原投递等待；已开始的阻塞构建继续持有真实许可直到工作和私有目录清理完成。
清理无法确认时关闭本实例的候选受理，不继续积累原文。

管理页面显式展示全部原目标的结果，过期、范围变化、隐藏或退出时清空旧事实。不自动审批、
执行或重试预览，不保存历史监控。结果只能说明本次观察，不能保证之后配置仍保持不变。
